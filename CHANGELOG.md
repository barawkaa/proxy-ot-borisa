# Changelog

## 1.25.5

- Исправлено отображение активных соединений auth-gateway: HTTP/SOCKS клиенты снова показывают реальные назначения/домены, а не `proxy-gateway`.
- SOCKS5 gateway больше не прокидывает первичное рукопожатие вслепую во внутренний proxy: backend читает целевой host/port, передаёт запрос во внутренний SOCKS и сохраняет назначение для UI, истории и маршрутов.
- Служебные соединения add-on отделены от клиентских: `proxy-gateway` больше не выглядит как сайт клиента и отображается как внутреннее служебное соединение.
- Вернулся отдельный раскрывающийся блок **Служебные соединения add-on**; раскрытые списки соединений и история сохраняют состояние при автообновлении.
- В истории клиентов HTTP/SOCKS-сессии получают имена зарегистрированных/доверенных клиентов и маршруты так же, как Telegram-клиенты.
- Диагностика на главной переработана: оставлена универсальная диагностика маршрутов и ручная проверка загрузки по URL без привязки к конкретным сервисам.
- Удалены UI/маршрутизационные упоминания частного сервиса и соответствующий пресет из продукта.

## 1.25.4

- Главная диагностика стала универсальной: вместо отдельной логики под конкретный сервис добавлен общий инструмент **Диагностика Proxy/VPN**.
- Добавлена **Проверка стабильности потока** по произвольному URL: проверяются два участка — внешний `auth-gateway` и внутренний `VPN-core/sing-box`.
- Диагностика даёт продуктовый вывод: проблема в маршруте, gateway/relay, внутреннем proxy/VPN, выбранной ноде или во внешнем сервисе.
- Исправлен relay `auth-gateway` для длинных потоков: non-blocking `sendall()` заменён на устойчивый двунаправленный blocking-relay с отдельными потоками и корректным half-close. Это должно устранить случайные обрывы больших HTTP/HTTPS-загрузок.
- Из главной диагностики убрана кнопка и жёсткая привязка к частному сервису; любые сервисы теперь проверяются через ручной ввод домена/URL.
- Сохранены улучшения v1.25.3: понятный маршрут соединений `auth-gateway → Proxy → VPN/DIRECT`, предупреждения по DIRECT и метка **trusted_ip без auth**.

## 1.25.3

- Добавлена проверка маршрута **Proxy/VPN** на главной странице: прямой внешний IP Raspberry, внешний IP через внутренний proxy, активный VPN-сервер, статус VPN и таблица доменов с решением `Proxy/VPN` или `DIRECT`.
- Добавлена кнопка **Проверить маршрут сейчас**: диагностика запускается из интерфейса и показывает, почему трафик пошёл напрямую или через VPN.
- Соединения auth-gateway теперь отображают полный понятный путь: `auth-gateway → Proxy → VPN: выбранный сервер` или `auth-gateway → Proxy → DIRECT`, с предупреждением, если финальный маршрут прямой.
- В карточках клиентов и активных соединениях восстановлена явная метка **trusted_ip без auth** для доверенных IP/CIDR, которые проходят без логина и пароля.
- Для синтетических соединений auth-gateway добавлен подсчёт Down/Up во время relay, чтобы активные HTTP/SOCKS соединения не выглядели как вечные `0 B / 0 B`.
- Добавлен backend endpoint `/api/route/diagnostics` для быстрой диагностики маршрута без ручных `curl`-проверок.
- Fast path доступа не усложнялся: проверка trusted/auth остаётся быстрой, а диагностика выполняется отдельным запросом и не должна задерживать клиентский трафик.

## 1.25.2

- Исправлено сопоставление автоматического трафика подписки с источниками серверов после миграции старых серверов: legacy/ранее добавленные серверы больше не должны ошибочно показываться как источник без автоматического трафика, если провайдер реально отдаёт лимит.
- Кнопка **Обновить трафик подписки** теперь возвращает не только `subscription_info`, но и актуальную модель `traffic_sources`, поэтому после нажатия обновляются вкладка **Трафик** и блок **VPN-подписка и лимит трафика** во вкладке **VPN-серверы**.
- Добавлен fallback **Трафик текущей подписки**: если провайдер отдал лимит, но источник невозможно однозначно сопоставить, данные отображаются отдельной строкой и не теряются.
- Во вкладке **VPN-серверы** блок подписки дополнен мини-сводкой по источникам трафика, чтобы информация совпадала со вкладкой **Трафик**.
- Fast path HTTP/SOCKS gateway не менялся: по замеру задержка через прокси была близка к прямому запросу, поэтому исправление сосредоточено на отображении и обновлении трафика.

## 1.25.1

- Обновлены README и инструкции под фактическую структуру интерфейса.

## 1.24.4

- Исправлен HTTP auth-gateway на штатных портах: обычные HTTP proxy-запросы и HTTPS `CONNECT` больше не должны сбрасываться gateway до передачи во внутренний `sing-box`.
- Внешняя схема остаётся без дополнительных trusted-портов: доверенные IP/CIDR работают без авторизации на штатных HTTP/SOCKS5 портах, остальные IP проходят через штатную авторизацию.
- HTTP gateway теперь сам обрабатывает `CONNECT` и обычные HTTP proxy-запросы, подключаясь к внутреннему `sing-box` через localhost SOCKS5.
- MTProto не затронут правилами HTTP/SOCKS trusted bypass: порт MTProto и идентификация пользователей по secret остаются отдельной логикой.
- Усилена проверка: старые trusted-порты 2085/2086 не используются, служебные поля приложения не попадают в конфиг `sing-box`.
