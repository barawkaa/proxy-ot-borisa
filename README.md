# Proxy от Бориса


> Текущая версия add-on: **1.25.2**. Архив собран как полноценный Home Assistant add-on repository: включает `repository.yaml`, корневой `README.md`, `CHANGELOG.md`, папку add-on и все файлы, необходимые для установки/публикации.

**Proxy от Бориса** — это Home Assistant add-on, который превращает вашу VPN/VLESS-подписку в управляемый HTTP/SOCKS5/Telegram MTProto прокси-шлюз.

Простыми словами: вы добавляете VPN-серверы или ссылку подписки, а add-on раздаёт удобный прокси для браузеров, телефонов, роутеров, приставок и Telegram. Через интерфейс можно выбирать сервер, смотреть пинг, контролировать клиентов, трафик, безопасность и маршрутизацию.

---

## Для чего нужен add-on

Add-on полезен, когда нужно:

- использовать одну VPN-подписку как общий прокси-шлюз;
- подключать устройства, где неудобно или невозможно установить VPN-клиент;
- раздать HTTP/SOCKS5 proxy для роутера, браузера, телефона или приставки;
- использовать Telegram MTProto proxy;
- отправлять через VPN только выбранные сайты и сервисы, а остальной трафик оставлять напрямую;
- видеть активных клиентов, соединения, трафик и логи;
- управлять пользователями и блокировками из веб-интерфейса.

## Основные возможности

### VPN и прокси

- импорт серверов из ссылки подписки;
- импорт `vless://` ссылок;
- импорт sing-box JSON;
- импорт JSON-массива серверов;
- импорт Clash YAML с VLESS-серверами;
- HTTP proxy;
- SOCKS5 proxy;
- Telegram MTProto proxy;
- ручной выбор VPN-сервера;
- автоматический выбор сервера;
- проверка пинга серверов;
- профили приоритета серверов;
- включение/выключение отдельных серверов;
- отдельное разрешение/запрет участия каждого сервера в auto.


### Источники VPN-серверов

Серверы теперь хранятся не только общим списком, но и с привязкой к источнику:

- подписка VPN;
- JSON-импорт;
- импорт ссылок;
- ручные серверы;
- ранее добавленные серверы после миграции.

Во вкладке **VPN-серверы** доступны два представления:

- **Список серверов** — общий пул, который используется для выбора сервера, ping и auto;
- **По источникам** — группировка серверов по подпискам/JSON/ручным источникам.

Для источника можно включить/выключить весь источник, отключить участие источника в `auto`, удалить все серверы источника или удалить конкретный сервер. Для каждого отдельного сервера также есть переключатели: включён/выключен и участвует/не участвует в `auto`. Исторические записи подключений при удалении серверов не стираются: история сохраняет факт, через какой маршрут шёл трафик в момент сессии.

### Маршрутизация

- весь трафик через VPN;
- только списки заблокированных ресурсов + ручные правила через VPN;
- только ручной список через VPN;
- всё напрямую, кроме Telegram;
- ручной список доменов/IP через VPN;
- ручной список исключений напрямую;
- обновляемые rule-set списки.


### Доверенный доступ без авторизации

Для устройств и программ, которые не умеют работать с proxy-auth, например браузерные расширения, ZeroOmega, Nintendo, Smart TV или некоторые роутеры, trusted-доступ работает на штатных HTTP/SOCKS5 портах:

- дополнительные внешние порты не открываются;
- если IP клиента есть в доверенном списке, логин и пароль не требуются;
- если IP неизвестный, используется штатная авторизация HTTP/SOCKS5;
- список доверенных IP/CIDR настраивается в разделе **Безопасность → Доверенный доступ без авторизации**.

Рекомендуется добавлять конкретный IP устройства, например `192.168.1.35`, а не всю сеть. Не используйте `0.0.0.0/0`: это фактически отключит авторизацию для всех.

### Клиенты и пользователи

- отдельные пользователи с логином и паролем;
- отдельные Telegram MTProto secrets;
- список клиентов онлайн/оффлайн;
- доверенные и неизвестные клиенты;
- ручные блокировки;
- лимит трафика клиента в GB/месяц;
- журнал событий по клиентам;
- агрегированная история активности по доменам/IP без перехвата содержимого HTTPS.

### Безопасность

- отдельная главная вкладка **Безопасность**;
- верхний мониторинг состояния доступа;
- подвкладки: доверенный доступ, авторизация и порты, RU-фильтр, автоблокировка, блокировки и события;
- авторизация SOCKS5;
- опциональная авторизация HTTP;
- trusted bypass на штатных HTTP/SOCKS5 портах;
- белые и чёрные списки IP/CIDR;
- RU CIDR-фильтр;
- автоблокировка подозрительных IP;
- связь со вкладкой **Блокировки**, которая остаётся основным рабочим списком блокировок;
- диагностика ошибок API.

### Мониторинг

- текущий сервер и пинг;
- состояние sing-box;
- состояние Telegram MTProto;
- данные по трафику VPN-подписки;
- срок действия подписки;
- активные соединения по клиентам;
- диагностические логи.

## Поддерживаемые форматы серверов

Сейчас основной гарантированный протокол — **VLESS / VLESS Reality**.

Поддерживаются следующие варианты добавления серверов:

1. **Ссылка подписки**  
   Например ссылка от VPN-провайдера. Add-on пробует загрузить её с разными User-Agent, как обычные VPN-клиенты.

2. **`vless://` ссылки**  
   Можно вставлять одну или несколько ссылок.

3. **sing-box JSON**  
   Подходит, если у вас уже есть готовый конфиг или список `outbounds`.

4. **JSON-массив серверов**  
   Можно вставить список серверов в формате JSON.

5. **Clash YAML с VLESS proxies**  
   Add-on умеет вытащить VLESS-серверы из блока `proxies:`.

Протоколы VMess, Trojan, Shadowsocks и другие могут встречаться в подписках, но в текущей логике add-on ориентирован на VLESS. Чтобы не было путаницы: если подписка содержит не VLESS-серверы, они могут быть пропущены.

## Как это работает

Схема работы:

```text
Устройство → Proxy от Бориса → выбранный VPN/VLESS-сервер → интернет
```

Пример:

```text
Браузер / роутер / телефон / Telegram
        ↓
HTTP, SOCKS5 или MTProto
        ↓
Proxy от Бориса
        ↓
VLESS Reality сервер
        ↓
Интернет
```

## Добавление подписки

Откройте вкладку **VPN-серверы** и вставьте ссылку подписки.

После успешного обновления add-on покажет:

- статус подписки;
- количество серверов;
- использованный трафик;
- остаток трафика;
- общий лимит;
- дату окончания подписки;
- User-Agent, с которым подписка успешно открылась.

Если подписка отдаёт заголовок `Subscription-Userinfo`, add-on использует его для отображения трафика.

## JSON подписки

Во вкладке **VPN-серверы → JSON подписки** отображается нормализованный JSON, который add-on получил из ссылки подписки.

Это удобно для проверки и аварийного восстановления: JSON можно скопировать и позже вставить как обычный импорт серверов.

## Профили приоритета серверов

Вместо непонятных чисел используются профили:

- **Приоритетный** — основной сервер, участвует в автоматическом выборе;
- **Обычный** — стандартный рабочий сервер;
- **Резервный** — используется вручную или как запасной;
- **Российский/резервный** — обычно не нужен для обхода блокировок, лучше держать в резерве;
- **Только вручную** — не участвует в auto, но доступен для ручного выбора.

После изменения нескольких серверов нажмите **Сохранить все приоритеты**.

---

## Трафик по источникам

Во вкладке **Трафик** данные разделены по источникам серверов, чтобы разные подписки и ручные серверы не смешивались в одну непонятную полосу.

Отдельно отображаются:

- подписка с автоматическим трафиком провайдера;
- дополнительные подписки, если провайдер отдаёт для них отдельные данные или если для них задан ручной лимит;
- ручные серверы и JSON-импорт без автоматического счётчика;
- ручные лимиты для VPS, сторонних подписок и отдельных групп серверов.

Если у источника нет автоматического лимита, он отображается как **лимит неизвестен**. Для него можно добавить ручной источник трафика: название, лимит, использовано и комментарий.

Кнопка **Обновить трафик подписки** повторно обращается к основной подписке и обновляет данные от провайдера. После обновления одна и та же модель трафика используется в двух местах: во вкладке **Трафик** и в блоке **VPN-подписка и лимит трафика** на странице **VPN-серверы**.

Для старых установок предусмотрено устойчивое сопоставление: если серверы были добавлены до появления источников и числятся как «Ранее добавленные серверы», автоматический лимит подписки всё равно привязывается к подходящему источнику по URL, типу подписки, единственному заполненному источнику или количеству серверов. Если сопоставить источник нельзя, трафик показывается отдельной строкой **Трафик текущей подписки**, чтобы данные провайдера не пропадали.

## Безопасность

Откройте главную вкладку **Безопасность**. Раздел разбит на подвкладки, чтобы не искать нужные настройки в общей простыне:

- **Доверенный доступ** — IP/CIDR, которым разрешён HTTP/SOCKS5 без логина и пароля;
- **Авторизация и порты** — контроль штатных портов и состояния auth;
- **Геофильтр RU** — входящий фильтр по российским IP и ручные allow/deny CIDR;
- **Автоблокировка** — лимиты и исключения автобана;
- **Блокировки** — сводка и быстрый переход к отдельной вкладке **Блокировки**;
- **События** — предупреждения и переходы к логам/аудиту.

Рекомендуется:

- не открывать HTTP без авторизации наружу, если это не требуется;
- использовать SOCKS5 с логином и паролем;
- создавать отдельных пользователей;
- включить автоблокировку для неизвестных IP;
- добавить доверенные IP/CIDR в исключения;
- использовать RU CIDR-фильтр только если вам действительно нужен доступ только из России.

Важно: если за одним роутером много устройств, не баньте такой роутер по количеству соединений. Добавьте его в доверенные или исключения автоблокировки.

## Типовая настройка

Для большинства пользователей подойдёт такая схема:

1. Добавить ссылку подписки.
2. Нажать **Обновить подписку**.
3. Нажать **Пинг всех серверов**.
4. Поставить зарубежным серверам профиль **Приоритетный** или **Обычный**.
5. Российские серверы поставить в **Российский/резервный**.
6. Выбрать режим маршрутизации **списки + ручной ввод**.
7. Создать пользователей.
8. Настроить порты и проброс на роутере.
9. Проверить систему во вкладке **Настройки → Проверка системы**.

## Актуальная продуктовая логика

README описывает текущее состояние add-on, а история изменений ведётся в `CHANGELOG.md`.

Ключевая логика актуальной версии:

- VPN-серверы имеют источники: подписка, JSON-импорт, ручные серверы, ранее добавленные серверы.
- Каждый сервер и каждый источник можно включать/выключать отдельно.
- Для `auto` сервер используется только если включён сам сервер, включён его источник, сервер разрешён для `auto` и источник разрешён для `auto`.
- Служебные поля приложения (`enabled`, `use_in_auto`, `source_id` и другие) не должны попадать в чистый конфиг `sing-box`.
- История и активность клиентов хранят только технические метаданные: клиент, домен/IP, маршрут, время, счётчики и трафик. Содержимое HTTPS, логины, пароли, формы и cookie не перехватываются.
- Все журналы, кэши и рабочие файлы должны быть видны в обслуживании или явно описаны как системные.

## Хранение данных, журналы и обслуживание

Add-on контролирует свои рабочие файлы через внутренний реестр `DATA_REGISTRY`. Это сделано для того, чтобы новые журналы, кэши и служебные файлы не появлялись «втихую» и не росли бесконечно.

Во вкладке **Настройки → Обслуживание** по каждому файлу отображается:

- путь к файлу;
- размер;
- количество записей;
- содержит ли файл секреты;
- входит ли файл в резервную копию;
- есть ли автоматическая очистка;
- зачем файл нужен;
- что с ним можно делать пользователю.

Основные лимиты хранения:

- история клиентов — 30 дней или 2000 последних сессий;
- MTProto activity — 30 дней или 1000 записей;
- аудит — 5000 событий;
- технические события — 2000 событий;
- кэш геолокации IP — 7 дней или установленный лимит записей;
- временные счётчики автобана — очищаются по рабочему окну автобана;
- автобэкапы `servers.json` — только 5 последних копий.

Автобэкапы `servers.json` создаются перед изменениями списка VPN-серверов. Они нужны для аварийного отката, могут содержать чувствительные параметры серверов и не включаются в обычный backup. Старые копии удаляются автоматически.

Раздел **Инструкции** внутри add-on разделён на раскрываемые группы и описывает не только настройку прокси, но и скрытые процессы: хранение данных, журналы, очистку, backup и обслуживание.

### Отображение клиентов и Telegram MTProto

В списке клиентов карточка зарегистрированного клиента показывает имя пользователя в заголовке, а IP отображается отдельной строкой внутри карточки. Незарегистрированные клиенты отображаются по IP.

Telegram MTProto-клиенты идентифицируются по индивидуальному secret. Если приложение может безопасно сопоставить secret с единственным активным внешним MTProto IP, в карточке отображаются IP, гео, провайдер и ASN. Если сопоставление неоднозначно, приложение не угадывает IP и показывает «IP клиента не определён», сохраняя идентификацию по secret.
