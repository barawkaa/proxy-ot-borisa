# Обязательные проверки выпуска

Это исполняемый порядок работы и указатель на автоматические проверки, а не обещание отсутствия ошибок.

| Требование | Проверка перед выпуском |
| --- | --- |
| Полная версия и история отката | Версия config.yaml, Python, HTML; неизменяемые прежние теги; новый релиз после CI |
| Обновление в HA | Браузер с service worker, который воспроизводит CacheFirst + ignoreSearch для /static/; старые файлы 5.0; воспроизведение сбоя 5.1; переход на новую версию без очистки кеша |
| Логотип | Прозрачность файла, фактические размеры 56×56 на компьютере и телефоне; размеры при недоступном CSS |
| История | Общий список, фильтр активных и завершённых подключений по клиенту, возврат ко всем; события диагностики после персонального фильтра |
| Главная без журнала задач | Текущие, завершённые и ошибочные задачи не создают верхний журнал; прогресс в карточке сервера; результаты в диагностике |
| Ручное переключение | Успех только после подтверждения; отказ сохраняет настройки и восстанавливает проверенный прежний маршрут либо закрывает VPN-маршрут |
| Работа из образа | ARM64 образ запускается; браузер открывает интерфейс этого образа, проверяет логотип, страницы и создание клиента |
| Сервисы и взаимосвязи | Модульные/API-тесты; реальный sing-box HTTP/SOCKS/trusted/переключение/восстановление; MTG запуск и статистика |
| Ошибки и неиспользуемый код | Python compileall, Ruff F, node --check; проверка diff и списка файлов |
| Публикация | Успех всех jobs точного кандидата и main; tag указывает на проверенный main; предыдущие релизы сохранены |

Проверка через модель маршрутизации кеша HA не равна запуску установленной у Бориса версии HA. Сообщать это ограничение. Реальные блокировки провайдера, доставка Telegram, Nintendo/Keenetic и длительная работа Raspberry Pi требуют отдельной проверки в домашней сети; не выдавать их за выполненные в CI.
