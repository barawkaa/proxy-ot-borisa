# Версии и откат

## Два независимых уровня

1. GitHub хранит **исходный код** каждой выпущенной версии: тег и Release. Старые теги не передвигаются. Ветка `archive/v4.0.2` уже сохраняет исходный commit.
2. Резервная копия дополнения Home Assistant хранит **установленное приложение и его данные**. Перед первым переходом на 5.0 её нужно создать в Home Assistant.

Самый простой откат — восстановить резервную копию дополнения, созданную перед обновлением. Один лишь checkout старой версии не возвращает клиентские пароли и настройки к прежнему состоянию.

## Данные 5.0

- `config-v5.json` — текущие настройки и секреты.
- `config-v5.previous.json` — предыдущая конфигурация.
- `history-v5.sqlite` — ограниченная история и месячный учёт трафика.
- Исходные JSON 4.x сохраняются без изменений; старая версия продолжит читать их.
- Новые клиенты/правила, созданные после перехода на 5.0, не появятся в 4.x автоматически.

В 5.1 экспорт/восстановление настроек из интерфейса удалены. Секреты остаются в данных дополнения; не публикуйте их на GitHub. Резервное копирование данных выполняет Home Assistant.

## Выпуск

Каждый релиз содержит полный исходный комплект. `v4.0.2`, `v5.0` и `v5.1` сохраняются, новая версия — `v5.2`. Workflow читает версию из проверенного commit, создаёт новый тег и Release; существующий тег не передвигает. ZIP/tar.gz доступны на странице релиза.

Откат с 5.1 на 5.0: предпочтительно восстановление резервной копии дополнения Home Assistant, сделанной до обновления. GitHub хранит код, но не личные настройки и не данные установленного приложения. Формат данных 5.x совместим; новые поля 5.1 старая версия не использует.

Откат с 5.2: восстановить резервную копию дополнения HA, сделанную перед обновлением. Формат данных 5.x сохранён. При возвращении на 5.1 известный конфликт старых /static/ ресурсов с кешем HA может проявиться снова; версия 5.1 хранится в истории без изменений.
