# Версии и откат

## Два независимых уровня

1. GitHub хранит **исходный код** каждой выпущенной версии: тег и Release. Старые теги не передвигаются. Ветка `archive/v4.0.2` уже сохраняет исходный commit.
2. Резервная копия дополнения Home Assistant хранит **установленное приложение и его данные**. Перед первым переходом на 5.0 её нужно создать в Home Assistant.

Самый простой откат — восстановить резервную копию дополнения, созданную перед обновлением. Один лишь checkout старой версии не возвращает клиентские пароли и настройки к прежнему состоянию.

## Данные 5.0

- `config-v5.json` — текущие настройки и секреты.
- `config-v5.previous.json` — предыдущая конфигурация.
- `history-v5.sqlite` — ограниченная история и месячный учёт трафика.
- Исходные JSON 4.x сохраняются без изменений; старая версия продолжит читать их.
- Новые клиенты/правила, созданные после перехода на 5.0, не появятся в 4.x автоматически.

Экспорт JSON из интерфейса содержит секреты. Не прикладывайте его к публичным issues и не коммитьте в GitHub.

## Выпуск

Ветка разработки `release/5.0` проверяется в Actions. В `main` попадает только проверенный комплект. Workflow выпуска после успешной проверки `main` создаёт теги `v4.0.2`, `v5.0` и GitHub Release 5.0. Исходные ZIP/tar.gz доступны у тега. Для новой пользовательской версии — полный комплект, новая запись истории и отдельный тег; скрытых исправлений выпущенного тега нет.
