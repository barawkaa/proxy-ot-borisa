# Проверки 5.3

## Автоматизировано

- Unicode-названия, Base64/URI, Xray JSON, Clash YAML, отдельные протоколы, разные транспорты на одном адресе, независимость подписок.
- Ошибки импорта, отсутствие секретов в сообщениях парсера.
- Исключения маршрутизации, режим клиента, fail-closed при отсутствии VPN.
- Приоритет универсального сервера, резерв, устаревшие измерения, защита от частых переключений, ручной отказ.
- Атомарное сохранение, сохранение прежних секретов при миграции, очистка истории.
- Реальный sing-box: HTTP 407, HTTP CONNECT, SOCKS5, trusted HTTP, передача данных, история, перезапуск после завершения, отказ от плохой конфигурации.
- Реальный MTProxy: запуск и API статистики.
- Отдельная ARM64-сборка образа и запуск приложения из собранного образа.
- Браузерные сценарии: создание клиента, вкладки подписок, основные страницы, мобильная ширина.
- Загрузка подписки частями (chunked HTTP), полное чтение и ограничение размера ответа.

Результаты конкретной ревизии — в GitHub Actions. В локальной среде нативный сетевой бинарник не запускается надёжно; сквозные проверки выполняются в GitHub Actions без отключения соответствующего gate.

## Проверяется на установке Бориса после обновления

- Импорт конкретной подписки и сравнение с Happ в одной и той же сети.
- Блокировки российского провайдера и региональные ограничения сайтов.
- Реальная отправка/получение сообщений Telegram через публичный адрес.
- Продолжительная работа на Raspberry Pi 4 / HA OS.
- Nintendo Switch и Keenetic/trusted — отложено по договорённости до возвращения домой.

## Честные границы

- `403/429/451` — ограничение сайта, не доказательство полной недоступности VPN. Состояние отображается отдельно.
- В 5.3 проверка Telegram выполняет MTProto обмен с nonce. Входной шлюз связывает IP с аутентифицированным секретом. Проверка контрольного файла требует настройки бота; без неё приложение не заявляет доступность видео. Сквозной CI использует контролируемый MTProto-узел, а не личный аккаунт владельца.
- SOCKS5 поддерживает CONNECT/TCP. UDP ASSOCIATE и BIND отклоняются явно.
- Не все конфигурации Xray совместимы с sing-box: XHTTP, цепочки outbounds и сторонние Shadowsocks plugins не преобразуются с потерей параметров. Они отображаются как неподдерживаемые.
- Замена ядра при изменении состава серверов/клиентов может завершить соединения. Обычные проверки и выбор нового сервера не требуют перезапуска ядра.
- Месячный трафик — учёт приложением, не биллинг провайдера. Последние незафиксированные данные при аварийном отключении питания могут быть потеряны.

## Регрессии 5.1

Большой/малый выигрыш задержки; скачок замера; две подтверждающие проверки; приоритет универсального сервера; требования Telegram; провал итогового маршрута и следующий резерв; ручной режим; устаревшие результаты; отсутствие скрытого штрафа ChatGPT; предел одновременных проверок; миграция 5.0 без потери секретов; фильтр истории до LIMIT; отсутствие API копирования; исключение секретов из отчёта. Браузер проверяет общую/персональную историю, форму trusted, отсутствие экспорта настроек, загрузку логотипа и ширину пяти мобильных страниц.

Проверочные страницы с защитой от ботов могут отвечать 403/429. Это отдельный статус, не утверждение о причине отказа. Все зарубежные контрольные сайты могут быть доступны и без VPN: их успех подтверждает работу проверяемого туннеля до этих сайтов, но не гарантирует разблокировку любого ресурса.

## Регрессии 5.2

- Полное совпадение выдаваемых ресурсов с файлами, версия/хеш в URL, отказ для чужого идентификатора сборки.
- Ручной выбор: подтверждение, отказ, возврат к прежнему серверу, отказ самого возврата, отсутствие ложного успешного ответа и сохранения режима при отказе.
- Браузер: service worker с совпадающими правилами HA CacheFirst и ignoreSearch. Реальные файлы неизменяемых тегов v5.0 и v5.1, воспроизведение огромного логотипа, переход на 5.2 без очистки кеша. Размер логотипа проверяется также без CSS.
- История: оба клиента в активных/завершённых соединениях, отдельный клиент, возврат ко всем, общие события диагностики после фильтра.
- Браузер запускается также против реального ARM64 образа: версия, ресурсы, размеры логотипа, страницы на двух ширинах, создание клиента и персональная вкладка.

Это модель кеширования Home Assistant, а не полный HA OS стенд и не удалённая проверка установки Бориса. Проверку на реальной установке нельзя считать выполненной по одному CI.

## Сценарии 5.3

`test_release53.py`: очередь IP, одобрение, пауза, запрет, истечение и сохранение; только явные LAN CIDR; приглашения и привязка к IP; предел очереди; устаревший callback; nested migration без смены секретов; внутренние маршруты; проверка HMAC и времени Fake TLS; реальное соединение шлюза с отказом до исходящего запроса и отзывом активного туннеля; ошибочная авторизация и предел памяти; бот Home Assistant без getUpdates; проверка владельца; nonce MTProto; приоритет подтверждённой загрузки; ограниченная загрузка и зависание.

`test_integration.py`: дополнительные проверки реального MTG через защищённый вход, неправильного секрета, HTTP по IP с запретом частного назначения, полного Fake TLS/обфускация/MTProto обмена с контрольным дата-центром. Контрольный дата-центр не заменяет проверку Telegram в сети пользователя.

`ui_test.cjs`: разрешение, пауза и запрет IP, единая строка результата ручной проверки; новые страницы на мобильной ширине. `image_ui_test.cjs`: те же страницы из запускаемого ARM64 образа.

Функция загрузки медиа тестируется с контролируемым клиентом и ограниченными фрагментами. Действующие API-данные контрольного бота владельца не предоставлены; реальную авторизацию и загрузку его файла нельзя считать выполненными. После настройки приложение проводит эту проверку автоматически и показывает отдельный результат.
