1. Базовая логика приложения

Что делает add-on

Он берёт VPN/VLESS-серверы и отдаёт их наружу как удобные прокси: HTTP, SOCKS5 и Telegram MTProto. Клиенты подключаются к твоему серверу, а сам add-on уже отправляет трафик через выбранный VPN-сервер или напрямую по правилам маршрутизации.

Основной порядок настройки

  1. Добавить VPN-подписку или отдельные серверы во вкладке VPN-серверы.
  2. Проверить ping серверов и оставить auto либо выбрать конкретный сервер.
  3. Создать пользователей во вкладке Пользователи.
  4. Проверить порты во вкладке Порты и доступ и пробросить нужные порты на роутере.
  5. Настроить устройства: браузер, роутер Keenetic, Telegram MTProto или другие клиенты.

2. VPN-серверы и подписки

Ссылка подписки

Если провайдер дал ссылку вида https://..., выбирай режим Ссылка подписки, вставляй URL в поле ссылки и нажимай Обновить подписку. При успешном обновлении серверы появятся в списке ниже.

JSON подписки

В под-вкладке JSON подписки можно вставить ссылку подписки и преобразовать её в JSON. Это нужно для проверки, что именно пришло из подписки, и для ручного импорта/резервного копирования списка серверов.

Приоритеты серверов

Приоритетный и Обычный участвуют в auto-выборе. Резервный лучше использовать как запас: он не должен автоматически перетягивать трафик, если нужен только на случай аварии.

3. Пользователи и доступы

Как выбирать тип пользователя

При создании пользователя выбирай понятный тип доступа: только Telegram MTProto, только SOCKS5, только HTTP, SOCKS5+HTTP или все сервисы. Для учёта и безопасности лучше делать отдельного пользователя под каждое устройство/человека.

Почему не стоит раздавать один доступ всем

Если один логин или один Telegram secret выдать нескольким людям, приложение не сможет честно разделить статистику и историю. Правильная схема: один пользователь — один человек/устройство/роутер.

Включение и выключение

Переключатель рядом с пользователем включает или отключает именно его доступ. Это не выключает весь прокси-сервис. Общие HTTP/SOCKS5/Telegram включаются в Обзоре.

4. Telegram MTProto

Что вводить в Telegram-клиент

Обычно нужны три поля: сервер, порт и secret. Сервер — твой внешний IP или DDNS. Порт — общий MTProto-порт из вкладки Telegram. Secret — индивидуальный secret конкретного Telegram-пользователя.

Идентификация Telegram-пользователей

Telegram MTProto не использует логин/пароль. Пользователь определяется по индивидуальному secret. IP для мобильных клиентов ненадёжен, потому что он постоянно меняется.

5. Маршрутизация

Режимы

Всё через прокси удобно для проверки, но может гонять лишний трафик. Заблокированные + ручные списки обычно лучше для повседневной работы: обычные сайты идут напрямую, нужные домены — через VPN.

Ручные домены

Во вкладке Маршрутизация добавляй домены, которые должны идти через VPN: например chatgpt.com, openai.com, нужные CDN или API. Домены лучше писать без https:// и без пути.

6. Трафик и история

Трафик подписки

Если провайдер отдаёт лимит в заголовках подписки, приложение показывает лимит, использовано и остаток. Данные обновляются кнопкой и автоматически на вкладке Трафик.

Ручной учёт

Если добавлен отдельный сервер без общей подписки или провайдер не отдаёт лимит, заведи его в блоке Ручной учёт трафика. Это ручной журнал: приложение не знает лимит провайдера само, но помогает видеть остаток.

История подключений

История сгруппирована по клиентам: последний сеанс, количество подключений, суммарное время и раскрываемые детали. Журнал ограничен по времени и количеству записей, чтобы не забить диск.

7. Логирование и диагностика

Обычный режим

Для постоянной работы ставь уровень warn. Тогда sing-box не пишет каждое соединение в журнал, а оставляет только предупреждения и важные события.

Когда включать info/debug

info и debug нужны только на время диагностики: например, когда нужно понять, куда именно идёт трафик или почему сервер не выбирается. После проверки лучше вернуть warn, иначе журнал будет быстро разрастаться и станет нечитаемым.

Если после обновления UI открылся раньше backend

После установки новой версии контейнер может быть уже запущен, а backend ещё несколько секунд стартует. Интерфейс проверяет /api/health и повторяет запросы, но если Home Assistant показал временную ошибку — обычно достаточно подождать несколько секунд и открыть add-on снова.

8. Настройка Keenetic через Proxy Client

Важно по версии KeeneticOS. Официально Proxy Client появился в KeeneticOS 3.9, но для нормальной работы и актуального интерфейса лучше ориентироваться на KeeneticOS 5.x и новее. На старых версиях названия пунктов меню могут отличаться.

1. Установить компонент Proxy Client

  1. Открой веб-интерфейс Keenetic.
  2. Перейди: Управление → Настройки системы.
  3. Нажми Изменить набор компонентов.
  4. Найди и установи компонент Proxy client / Клиент proxy.
  5. Дождись установки и перезагрузки компонентов, если роутер попросит.

2. Создать proxy-подключение

  1. Перейди: Интернет → Другие подключения.
  2. В блоке proxy-подключений нажми Добавить подключение.
  3. Тип: обычно SOCKS5. Если нужен HTTP — выбирай HTTP.
  4. Сервер: внешний IP/DDNS твоего Home Assistant или сервера.
  5. Порт: SOCKS5-порт из add-on, обычно 2080; для HTTP обычно 2081.
  6. Логин и пароль: данные пользователя, созданного во вкладке Пользователи.
  7. Включи подключение переключателем.

3. Настроить домены, которые должны идти через proxy

  1. Перейди: Сетевые правила → Маршрутизация.
  2. Открой Маршруты DNS или раздел доменных списков, если он доступен в твоей прошивке.
  3. Создай списки доменов: например openai.com, chatgpt.com, youtube.com — только то, что реально нужно гнать через proxy.
  4. Создай правило маршрутизации: для этих DNS/доменных списков использовать созданное proxy-подключение.
Смысл такой: роутер сам решает, какие домены отправлять через proxy, а весь остальной интернет оставляет напрямую.

4. Настроить DNS через DoT/DoH

  1. Перейди: Сетевые правила → Интернет-фильтры → Настройка DNS.
  2. Добавь DNS-сервер.
  3. Интерфейс: можно выбрать любой/основной доступный интерфейс, если нет отдельного сценария.
  4. Адрес: 9.9.9.9.
  5. Имя TLS-сервера: dns.quad9.net.
Зачем это нужно: при proxy-подключении важно, чтобы DNS-запросы резолвились предсказуемо и не ломали доменную маршрутизацию. Официальная справка Keenetic прямо предупреждает, что доступ через proxy может работать некорректно, если устройства не используют DNS через DoT/DoH. Quad9 дополнительно фильтрует известные вредоносные домены. Это не строго обязательно для каждого сценария, но для схемы «домены через proxy, остальное напрямую» я бы считал это рекомендованной настройкой.

5. Проверка

  1. Открой на клиентском устройстве сайт, который должен идти через proxy.
  2. Во вкладке add-on Клиенты проверь, что роутер появился онлайн.
  3. Во вкладке Соединения проверь назначение и маршрут.
  4. Если домен идёт напрямую — проверь DNS-список и правило маршрутизации на Keenetic.
