1. Базовая логика приложенияЧто делает add-on и в каком порядке его настраивать.

Что делает add-on

Он берёт VPN/VLESS-серверы и отдаёт их наружу как управляемые прокси: HTTP, SOCKS5 и Telegram MTProto. Клиенты подключаются к твоему серверу, а add-on отправляет трафик через выбранный VPN-сервер или напрямую по правилам маршрутизации.

Основной порядок настройки

  1. Добавить VPN-подписку, JSON или отдельные серверы во вкладке VPN-серверы.
  2. Проверить ping серверов и оставить auto либо выбрать конкретный сервер.
  3. Создать пользователей во вкладке Пользователи.
  4. Проверить порты во вкладке Порты и доступ и пробросить нужные порты на роутере.
  5. Настроить устройства: браузер, Keenetic, Telegram MTProto, приставку или другие клиенты.
2. VPN-серверы, источники и подпискиКак различать серверы из подписок, JSON и ручного добавления.

Источники серверов

Каждый сервер имеет источник: подписка, JSON-импорт, ручной ввод или ранее добавленные серверы. В общем списке серверы остаются единым пулом для работы proxy и auto, но во вкладке По источникам видно, откуда каждый сервер появился.

Ссылка подписки

Если провайдер дал ссылку вида https://..., выбирай режим Ссылка подписки, вставляй URL, указывай понятное имя источника и нажимай Обновить подписку.

JSON подписки

В под-вкладке JSON подписки можно преобразовать ссылку подписки в нормализованный JSON. Такой импорт получает отдельный источник, чтобы его не путать с ручными серверами и основной подпиской.

Удаление серверов

Можно удалить отдельный сервер или все серверы источника. При удалении очищаются связанные ping/auto-данные, но история старых сессий сохраняется как исторический факт: она показывает, через какой маршрут трафик шёл в момент подключения.

Полный контроль серверов

Управление есть на двух уровнях: источник и конкретный сервер. Источник можно включить/выключить целиком, можно разрешить/запретить его участие в auto. Отдельный сервер тоже можно включить/выключить и отдельно исключить из auto красивым переключателем. Итоговый auto-пул строится только из серверов, у которых включены и источник, и сам сервер, и оба разрешения auto.
3. Пользователи и доступыКак создавать доступы и почему один пользователь не должен быть общим для всех.

Как выбирать тип пользователя

При создании пользователя выбирай тип доступа: только Telegram MTProto, только SOCKS5, только HTTP, SOCKS5+HTTP или все сервисы. Для учёта и безопасности лучше делать отдельного пользователя под каждое устройство/человека.

Почему не стоит раздавать один доступ всем

Если один логин или один Telegram secret выдать нескольким людям, приложение не сможет честно разделить статистику и историю.

Включение и выключение

Переключатель рядом с пользователем включает или отключает именно его доступ. Общие HTTP/SOCKS5/Telegram включаются в Обзоре.
4. Доверенный доступ без авторизацииДля браузеров, ZeroOmega, Smart TV, приставок и устройств без поддержки proxy-auth.

Для чего нужен trusted bypass

Некоторые клиенты не умеют передавать логин/пароль proxy, особенно SOCKS5 auth в браузерах и расширениях. Для них trusted-доступ работает на штатных HTTP/SOCKS5 портах: доверенные IP заходят без логина/пароля, остальные клиенты проходят обычную авторизацию.

Как настроить

  1. Открой главную вкладку Безопасность.
  2. Включи Доверенный доступ без авторизации.
  3. Добавь IP рабочего ПК, приставки, Smart TV или роутера, например 192.168.1.35.
  4. Открой Настройки → Порты и посмотри обычные HTTP/SOCKS5 порты.
  5. В ZeroOmega укажи IP сервера и обычный HTTP/SOCKS5 порт, поля логина и пароля оставь пустыми.

Безопасность

Trusted-доступ не должны быть открыты всем. Не добавляй 0.0.0.0/0. Лучше указывать конкретный IP устройства или узкую домашнюю подсеть, если ты понимаешь последствия.
5. Telegram MTProtoПорт, secret, статусы и ограничения идентификации.

Что вводить в Telegram-клиент

Обычно нужны три поля: сервер, порт и secret. Сервер — внешний IP или DDNS. Порт — общий MTProto-порт из вкладки Telegram. Secret — индивидуальный secret пользователя.

Идентификация Telegram-пользователей

Telegram MTProto не использует логин/пароль. Пользователь определяется по индивидуальному secret. IP мобильных клиентов ненадёжен, потому что постоянно меняется.

Статус онлайн

Статус строится по активности secret и имеет небольшой grace-период. Если Telegram сам держит соединение нестабильно или клиент спит, статус может стать «недавно был», а не мгновенно «оффлайн».
6. МаршрутизацияКакие домены идут через VPN, а какие напрямую.

Режимы

Всё через прокси удобно для проверки. Заблокированные + ручные списки обычно лучше для повседневной работы: обычные сайты идут напрямую, нужные домены — через VPN.

Ручные домены

Домены лучше писать без https:// и без пути: например chatgpt.com, openai.com, нужные CDN/API.

Проверка маршрута

Блок проверки маршрута показывает, почему домен пойдёт через VPN или напрямую. Это помогает не гадать, почему сайт открылся криво или часть ресурсов пошла мимо прокси.
7. Трафик, история и активностьЧто приложение фиксирует, а что не перехватывает.

Трафик подписки

Если провайдер отдаёт лимит в заголовках подписки, приложение показывает лимит, использовано и остаток. Если лимит неизвестен, используй ручной учёт.

История подключений и активность

История фиксирует метаданные: клиент, время, сервис входа, маршрут, домены/IP назначения и объём трафика, если он доступен. Дополнительно ведётся агрегированная активность по доменам/IP: первый/последний раз замечен, маршрут, сервис и счётчики. Приложение не перехватывает содержимое HTTPS, пароли, формы, cookie и личные сообщения.

Ограничения истории

Сессии клиентов хранятся 30 дней или 2000 последних сессий. Активные сессии не удаляются при автоочистке.
8. Хранение данных, журналы и очисткаЧто хранится внутри add-on и почему файлы не должны расти бесконечно.

Главный принцип

Все рабочие JSON-файлы должны быть зарегистрированы в DATA_REGISTRY. Если файл может расти, у него должен быть лимит, очистка и отображение в Обслуживании.

Основные лимиты

  • История клиентов — 30 дней или 2000 сессий.
  • MTProto activity — 30 дней или 1000 записей.
  • Аудит — 5000 событий.
  • Технические события — 2000 событий.
  • Кэш геолокации — 7 дней или лимит записей.
  • Временные счётчики автобана — очищаются по рабочему окну автобана.
  • Автобэкапы servers.json — только 5 последних копий.
  • Активность клиентов по доменам/IP — 30 дней или 10000 агрегированных записей.
  • Кэш rule-set маршрутизации — до 200 файлов; лишнее очищается.

Автобэкапы servers.json

Создаются перед изменением списка серверов, чтобы можно было восстановиться после ошибки импорта. Они могут содержать параметры VPN-серверов, поэтому считаются чувствительными. В обычный backup они не включаются, старые копии удаляются автоматически.

Обслуживание

Вкладка Обслуживание показывает путь файла, размер, число записей, секретность, участие в backup, наличие cleanup и понятное объяснение: зачем файл нужен и можно ли его чистить.
9. Логирование и диагностикаКак не превратить журнал в мусор.

Обычный режим

Для постоянной работы ставь уровень warn. Тогда sing-box не пишет каждое соединение, а оставляет только предупреждения и важные события.

Когда включать info/debug

info и debug нужны только на время диагностики. После проверки лучше вернуть warn, иначе журнал станет большим и нечитаемым.

После обновления add-on

UI проверяет /api/health и ждёт готовности сервисов. Если сам Home Assistant показал временную ошибку загрузки add-on, обычно достаточно подождать несколько секунд и открыть страницу снова.
10. Keenetic через Proxy ClientКак подключить роутер к локальному/внешнему прокси.
Важно по версии KeeneticOS. Proxy Client появился в KeeneticOS 3.9, но для нормального интерфейса лучше ориентироваться на KeeneticOS 5.x и новее.

1. Установить компонент Proxy Client

  1. Открой Keenetic.
  2. Перейди: Управление → Настройки системы.
  3. Нажми Изменить набор компонентов.
  4. Установи Proxy client / Клиент proxy.

2. Создать proxy-подключение

  1. Интернет → Другие подключения.
  2. Добавь proxy-подключение.
  3. Тип: SOCKS5 или HTTP.
  4. Сервер: внешний IP/DDNS твоего сервера.
  5. Порт: SOCKS5 обычно 2080, HTTP обычно 2081.
  6. Логин/пароль: данные пользователя из вкладки Пользователи.

3. Домены через proxy

В Сетевые правила → Маршрутизация создай списки доменов и правило, которое отправляет эти списки через proxy-подключение.

4. DNS через DoT/DoH

Для доменной маршрутизации желательно настроить DNS через DoT/DoH. Пример: 9.9.9.9 и TLS-имя dns.quad9.net. Это снижает риск, что провайдерский DNS сломает доменные правила.

Режим работы
Для постоянной эксплуатации используй Обычный. Диагностика временно включает подробные логи. Отладка нужна только для поиска ошибок. Безопасный блокирует изменения и оставляет просмотр/резервные операции для восстановления.
—
Логирование sing-box
Для обычной работы ставь warn: в журнал не будут сыпаться строки по каждому соединению. info/debug включай только на время диагностики.
Диагностика задержек
Проверяет не только ping в интерфейсе, а реальный HTTP/TCP delay через outbounds sing-box. Если обычный ping 100 мс, а здесь 600–1000 мс — проблема в конкретном VPN-узле, потерях, DNS/TCP или перегрузке маршрута.
